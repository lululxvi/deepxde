# Contributing to DeepXDE

First off, thank you for taking the time to contribute! It’s people like you who make this project better. To keep things running smoothly, please follow these guidelines.

---

## Code Style & Formatting

We use **Black** as our uncompromising code formatter to keep the codebase consistent.

* **Format before you commit:** Ensure your code is formatted by running:
```bash
black .
```

---

## Pull Request Guidelines

To ensure your PR is reviewed and merged quickly, please adhere to the following:

### 1. Minimal Changes (Keep it Focused)

* **One PR = One Task:** Avoid "scope creep." If you are fixing a bug and notice a typo in an unrelated file, please fix the typo in a separate, tiny PR.
* **Easier Reviews:** Smaller PRs are significantly easier to review and much less likely to introduce unintended side effects.
* **No "Drive-by" Refactoring:** Please don't reformat entire files or change variable names unless it is the specific goal of the PR.

### 2. PR Descriptions

* Briefly explain **what** changed and **why**.
* Link to any related issues (e.g., `Closes #123`).
* Include screenshots or terminal output if there are UI or CLI changes.

---

## The Review Process

* **New to the Repo?** Reviewing code is the fastest way to learn the architecture. Ask questions and point out things that are confusing.
* **Responsiveness:** Please try to address review comments within 48 hours. We also aim to provide reviews to PRs within 48 hours.

---

## Issues / Discussions

If you have found a bug in DeepXDE or want to make a feature request, please place it in the **issues** section. Otherwise, for questions about the library or requests for help, please use the **Discussions** section. This helps with separation of concerns and keeps the backlog more manageable.

## How to Start Contributing

DeepXDE is a complex multilibrary repo that may feel intimidating at first glance, but there are areas that are available for first-time contributors:

* **Documentation Fixes:** Multiple areas of DeepXDE are currently underdocumented; we appreciate well-written and researched documentation that follows our style guidelines.
* **Library Ports:** Often, DeepXDE functions don't support every library yet. Porting functions to different libraries is an easy way to contribute and learn.
* **Open an Issue:** DeepXDE is under active development, implementing new methods from the literature. If you find a bug or a new paper that is relevant to DeepXDE, please open an issue.
* **Answer Questions in Discussions:** Most aren't experts in DeepXDE yet; even if you can't answer the full question, pointing out what you notice is always helpful.
